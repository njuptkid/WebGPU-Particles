01 · 设计规则与参数基准

1. 最终范围与优先级

本包唯一的运动基本单元是细粒子。桌面对象和应用内容块是粒子来源，不是大粒子。

规则优先级：

  • 背景与内容分离；应用底色全程覆盖，不能出现透明窟窿。
  • 内容在原位从一侧逐渐转成粒子，反向逐渐凝聚；不能整屏或整块同步切换。
  • 粒子运动有明确下游方向，扰动在整个屏幕连续，涡流形状持续变化。
  • 粒子保留来源色彩，细颗粒与大颗粒混合，密度足够承接原内容。
  • 调整性能时先减少采样和离屏开销，保留以上视觉结构。

2. 背景与粒子内容

场景永久底层进入粒子的内容不进入粒子的内容
桌面独立壁纸icons / widgets / dock / status 等可见上层，包含标题、文字、文件夹图标与底框、卡片壁纸；机框与控制面板
应用内识别或宿主提供的应用底色完整卡片、封面、控件、文字等内容掩码被识别为背景的像素；机框；界面下方的桌面壁纸

桌面标题、图标不需要按“大粒子模式”的字 / 图标对象数划分。最终以图层中可见像素采样。壁纸可由产品另行管理为静态或动态，但不能混入内容粒子纹理；本包静态壁纸用于隔离核对粒子。

应用内先分块只是获得稳定的内容掩码、排除背景并标识采样归属。不对大卡片追加中心保护拆分 / 网格细分；不对块做平移、缩放或三维自旋。

3. 坐标与开合控制

以各自屏幕正视、屏幕内容正常可读的坐标定义左右，原点左上，x 向右、y 向下。机模三维视角、背面观察造成的视觉左右反转不改变算法坐标。

基准逻辑分辨率：内屏 1292×914，外屏 632×924。演示纹理及离屏渲染为逻辑尺寸的 2 倍。手机按实际纹理映射；不要把这两组尺寸理解成硬件限制。

设开合角度 a∈[0°,180°]，0 为闭合，180 为展平：

qOuter = clamp(a / 180)
qInner = 1 - clamp(a / 180)
tau(q) = 1.65 * pow(q, 0.78)

q=0 为完整内容，q=1 为仅背景。tau 是由开合进度算出的动效时钟，不是必须播放 1.65 秒。状态每帧从进度重算，不能为每个卡片另起一个独立计时器。

完整内容与粒子位置通过同一个 tau / birth 过渡。开合刚发生便进入连续计算；局部释放前沿仍由自身位置决定。禁止另加“先等 200 ms 才播放”的启动延迟。

4. 方向矩阵

默认交付配置：外屏从左向右凝聚（开关勾选）。direction 是“q 增大、内容消散”时的粒子位移方向，不是当前实际开合方向。反向播放自然表现为相反的汇聚方向。

实际操作外屏内屏
闭合 → 展开从完整界面逐渐粒化，粒子向左散去粒子从左侧向右流入，逐渐恢复界面
展开 → 闭合粒子从左侧向右流入，逐渐恢复界面从完整界面逐渐粒化，粒子向左散去

默认内外屏 shader direction=-1。若外屏开关取消：外屏消散向右、汇聚从右向左，shader direction=+1；内屏不变。详见 src/fold-clock.js。

注意：不同阶段看到的“粒化前沿推进”与“粒子已经产生后的运动”是两件事。direction=-1 时，右侧的释放阈值更低，界面从右向左逐渐碎化，生成粒子同时向左走；反向时从左向右逐渐恢复。不得只镜像粒子位置而不镜像释放阈值。

5. 渐进粒化 / 凝聚

源像素位置 p，u=p.x/W，方向 d，使用原版共同函数：

b = 0.045
  + mix(1.0-u, u, step(0.0,d))*0.50
  + noise(p*0.009)*0.18
  + hash(floor(p*0.65))*0.20;
age = max(0, tau - b);
remain = 1 - smoothstep(b, b+0.26, tau);
particleIn = smoothstep(0, 0.14, age);

重要约束：remain 在片元级源坐标计算，不能用卡片中心计算一次后让整张卡同透明度消失。粒子的 age 使用同一个源像素 birth。分块边界处共享同一个屏幕流场，不在每个块内重复从 x=0 开始计算。

噪声只打破笔直扫描线，方向梯度必须看得出来。粒子出现与原内容减少存在交叠，避免先看到空白、再看到粒子。极端端点直接显示原界面 / 稳定背景，避免残余尘点。

6. 粒子运动与扭曲

transport.glsl 是共同轨迹基准：粒子拥有独立的速度、横向扩散、尺寸与寿命种子。主要位移沿 d 单调下游推进；大尺度涡流与带状弯曲只修改纵向，避免一半粒子向上游打转。

共同流场包含两组随进度向下游推进的涡区、随 fieldTime 演化的半径与相位、横向压缩形成的疏密变化。既不能每颗纯随机抖动，也不能每个图标保留一个固定团簇。

应用内在共同 transport 上使用确认版参数：x 位移倍率 1.45；叠加连续域扭曲，尺度 q=(d*x−tau*210)*0.0035、y*0.004；低频幅度 180、高频幅度 58；相位 fieldTime*0.93。扰动从源像素坐标计算，跨卡片连续。无卡片整体搬运，无粒子绕卡片中心的公转。

fieldTime 是秒单位的相位时间。演示在固定角度也能看到扭曲形状演变。手机应在一次开合会话内连续计时；反转时不要重置。固定 fieldTime + 相同开合角度 + 相同快照必须产生确定性结果。完全静止 / 后台时可按产品策略停止渲染。

7. 密度、尺寸、颜色

参数当前基准含义 / 不可误读事项
sampleStep1.5 逻辑 px原型高密度基准，手机必须调预算；不是物理像素

8. 背景与透明度

应用底色取本地截图中主要中性色颜色簇平均值；宿主能提供主题 / Surface 色时优先传入宿主底色。样例内屏 RGB(25,25,27)，外屏 RGB(24,24,26)，这是识别结果，不能硬编码到所有应用。

原型背景中未识别的残余细节会在原位淡出，但底色始终存在。真机应尽量通过内容树补全遗漏；复杂多色 / 渐变背景要传背景层，不应强行全局取一色。当前全局中性色识别属于单底色界面的近似实现。

纹理、shader 输出、混合必须统一预乘 alpha。基准 blend=ONE / ONE_MINUS_SRC_ALPHA。源色需要时先除 alpha 得到直色，再在 fragment 输出中乘回一次 alpha。不要用黑底 JPEG 代替透明桌面图层，不要再次相乘导致转化边缘发黑。

02 · 详细示例与失败对照

A. 桌面：图标、标题、卡片同时属于可见内容

输入样例见 demo/assets/desktop-{inner,outer}-content.png（透明底）和对应 wallpaper.png。content 包含 widgets、icons、dock、status 四类上层的合成；壁纸不在 alpha 掩码内。

假设外屏一个图标包围框 x=80..150，标题 x=70..160。不要把两者各变成一个大的纹理平面飞走。对透明合成图按 1.5 逻辑像素间距采样，只有 alpha>16/255 的源像素产生点。图标的形状与文字笔画会自然保留在释放初期，随后被统一流场拉散。

同一图标左右笔画的 birth 不同，因此边缘能看到逐渐碎化。大时钟“10:08”也按笔画像素碎化，不拆成五张整体飞行的纹理。文件夹内部所有可见像素均可采样；不要把文件夹底框整体当作一个粒子。

内屏出现阶段 q 从 1 减小到 0：源纹理从左往右逐渐恢复，粒子沿从左往右的实际动势收敛。端点 q=0 必须像素级恢复输入内容＋壁纸，不能剩下最后一层漂浮的尘。

B. 应用外屏：完整主视觉原位碎化

原始截图见 demo/assets/app-outer.jpg。识别叠图见 examples/app-outer-识别预览.jpg；精确逻辑坐标以 examples/app-blocks.json 为准，不能把本文近似尺寸作为固定模板。

典型结果：

内容示例识别结构运动规则
顶部主视觉一张约 632×510 的大卡片，含图中标题、人物和覆盖在主视觉内的内容整卡不追加切线、不平移；卡片内像素按全屏横坐标逐渐碎化
底部封面三个独立封面，约 190×195分别保留掩码归属，进入同一流场

浮动导航栏独立控件；覆盖关系保留，不能与封面重复拥有同一像素与其他内容共享前沿；不要重复采样造成导航区域发亮

样例外屏总计 10 个卡片 / 控件块＋2 组文字，即 12 个采样内容单元。主视觉中“人物”没有被语义抠图，是完整主视觉卡片的一部分。

默认外屏从左向右凝聚：展开时，右侧先碎化、粒子向左走；闭合时反播，左侧先建立界面、右侧稍后完成。宏观扰动跨越主视觉、封面和控件，使粒子不像多个独立方形云团。

C. 应用内屏：横幅保持完整

内屏原图与识别图分别见 demo/assets/app-inner.jpg、examples/app-inner-识别预览.jpg。典型识别为两张完整横幅、六张封面和多个搜索 / 分类 / 导航控件。

样例内屏为 20 个卡片 / 控件块＋6 组文字，共 26 个采样内容单元。较大横幅约 592×335；它仍是一张卡片，不能沿中心拆为三块。全部未被别的块覆盖的可见像素由同一块拥有，圆角与遮挡由 alpha 掩码保留。

需要关注的中间态：右侧横幅可已经大量变成粒子，左侧横幅仍保留大部分内容；同一横幅自身也有渐进碎化，而不是两张横幅依次整张淡掉。识别是局部的，释放前沿与运动场是全屏连续的。

D. 用角度理解双屏过程

角度外屏 q内屏 q理想观察
0°01外屏完整，内屏仅底层
30°.167.833外屏一侧开始粒化；内屏粒子已经可见，无长时间全空
60°.333.667外屏存在明显方向性过渡带；内屏正在从粒子恢复
90°.5.5双屏均处于连续中间态；不能在系统折叠阈值上突变
120°.667.333外屏主体粒子化，内屏大部分内容恢复但仍有方向性边界
150°.833.167内屏趋近完整，外屏仍有残余流动并接近背景
180°10内屏完整，外屏仅底层

实际完整率受源图、噪声和 tau 非线性映射影响；表格不是硬切状态或新加时间段。4 秒机模视频包括先开后合两段，是展示节奏，不是要求手机每次动作都固定 4 秒。

E. 输入新界面的示例流程

收到 fold 开始事件
→ 固定本次出屏快照 revision=R17
→ 后台对低分辨率副本检测块 / 背景色
→ 掩码与 sourceTexture 必须同属 R17
→ 生成本次静态粒子 buffer，只更新进度和相位
→ 新屏幕布局已就绪时，使用其独立快照 R18 建立入屏内容
→ 整次会话冻结各自资源，不在中间把 R17 的图替换为 R19
→ 进度到端点后，交回真实 UI；后台释放不再需要的纹理

两块屏幕的布局可以不同，粒子不需要一一对应。颜色和运动让视觉连贯，但不能为了“一一对应”强行把外屏卡片拉伸成内屏卡片。

03 · 手机端实现方案

1. 推荐分工

以系统 / 桌面 / 窗口合成层能够控制内外屏 Surface 为前提，分成四个独立模块：快照输入、内容分离、粒子渲染、折展进度协调。不要依赖浏览器机模、截图视频或 JS 页面来驱动手机产品。

Fold / VSync / Window lifecycle
             ↓
FoldController → FrameUniforms → NativeParticlePass → Screen Surface
       ↓                             ↑
SnapshotProvider → Worker extraction → PreparedSnapshot (revision + fence)
       └──── wallpaper / app base color (separate background pass)

src/contracts.d.ts 描述数据契约。src/native/fold_clock.hpp 只有可移植数学，不包含 SDK 桥接。GLSL 用 WebGL1 / GLES2 风格，可移到 GLES；Vulkan / 其他着色语言需转换接口与资源布局，不是直接改后缀。

2. 从真实 UI 获取输入

桌面优先从自有渲染树或已知图层取得“壁纸”和“上层内容”。这比从壁纸合成后的整屏截图重新识别图标可靠。桌面 source 必须是透明底，壁纸单独传给 background pass。

应用内只有截图时，运行本包 ContentRegions 检测。若宿主能提供可见卡片边界、圆角、裁剪和实际背景色，则优先由宿主提供，图像识别作为兜底。宿主元数据与截图必须在同一内容版本，且按照视觉遮挡确定所有权。

普通 App 不应假设有权限截取其他 App、锁屏或系统保护 Surface。系统 / 桌面集成方提供允许的快照 / 图层句柄；受保护内容用产品定义的占位或普通过渡，不绕过系统限制。Android 的 HardwareBuffer 仅是共享缓冲资源能力示例，不自动获得任意应用截图权限。官方 HardwareBuffer 文档

本包演示图片导入与真实手机跨应用取图不是同一个问题；接口必须由目标团队实现并验证。

3. 应用分块步骤

  • 将截图分析副本缩放到短边 320，保留宽高比；原始高分辨率纹理用于最终显示。
  • 在中性色 RGB 量化直方图中找主簇，平均得到背景色；按颜色差建立前景掩码。
  • 形态学闭运算连接抗锯齿断边，连通域找到卡片与控件候选。
  • 对被底部浮层连接的封面行，分析上部持续竖向间隙拆出封面；对胶囊控件校验闭合边缘。
  • 大卡片优先，压制内嵌纹理误检；保留浮层遮挡；对未占有的文字做连通组。
  • 为每个源像素给出唯一 owner ID；小断边根据邻域归属附着。每块保留真实 alpha 掩码，不能只输出矩形裁切。
  • 对全部卡片 / 控件 / 文字块分别采样，跳过背景；不做大卡片二次切分。
  • 不属于内容块的残余区域单独绘制，其细节可原位淡出；应用底色永久画满。

详见 src/content-regions.js 与 src/app-block-extractor.js。检测是启发式图像处理，不是 OCR / 语义 AI，不保证任意截图都完整正确。深色、浅色、复杂摄影背景、透明控件和渐变都应加入真实测试集。

4. 避免准备时间吃掉动画

本包 build() 为便于读懂仍是同步 CPU + Canvas 参考实现，生产禁止在 UI / 渲染线程临时照搬这段全流程。

推荐：低分辨率分析放工作线程；原截图留在 GPU；把 owner / mask 作为低分辨率纹理或稀疏区域索引上传。用 source UV + mask 取样，不逐块复制高分辨率截图。粒子顶点 / 实例缓冲只在快照变更时创建。

后台缓存键至少包括屏幕、实际尺寸、contentRevision、主题、适配方式和识别参数。现有原型只按屏幕与参数缓存，是固定示例素材的简化，不能直接用于“每次都是新界面”的手机。

开始折展时的次序：

若有匹配本次 revision 的 PreparedSnapshot：立即使用
否则保持当前真实界面，同时后台准备低分辨率分析
若准备在约定首帧截止前完成：原位接入细粒子
否则：本次使用快速内容掩码 / 宿主布局，或产品批准的普通过渡

建议准备截止目标 1–2 个显示帧，仅为工程目标，不是已达到指标。不能阻塞合页输入，不能等 100 ms 再从头重播；也不能用上一张应用界面的切片假装已准备。复杂界面超时应记录原因，具体降级需设计 / 开发共同确认。

5. GPU 数据与绘制

原生建议数据：源纹理、owner / alpha 纹理、可选 block bounds、静态样本缓冲、背景纹理 / 底色。每个样本至少含全局源位置与随机种子；block ID 可用于调试、采样配额和失效重建，不作为整块位移矩阵。

每帧仅更新 resolution、tau、direction、fieldTime 与输出倍率。顺序：

  • 画桌面壁纸或不透明应用底色。
  • 应用残余细节在原位淡出，始终有底色填充。
  • 画内容纹理：对源像素算 birth / remain，几何位置固定。
  • 画柔边点精灵：相同 birth 计算 age，从源像素起点进入全屏流场。
  • q=0 交给真实完整界面；q=1 只保留底层。静止时不重复积累或清空后漏画。

粒子位置用源坐标 + 解析轨迹，不在 CPU 每帧更新几十万个点。GPU 并行计算；不需要先上 compute 才能实现。平台点精灵尺寸范围、精度和驱动行为不满足时，用实例化小四边形替代 GL_POINTS，并保持相同柔边和尺寸分布。

WebGL UNPACK_PREMULTIPLY_ALPHA_WEBGL 是浏览器特有设置，原生上传时要查清 PixelMap / Buffer 的实际像素格式和 alpha 约定，不能假设原生会自动做相同转换。HDR / 广色域必须明确采样与混合色域，不把 sRGB 参考值直接套在线性空间。

6. VSync 与时间

foldAngle 决定转化进度，VSync 决定提交节奏，fieldTime 决定持续的涡流形状。反转开合时不重置 seed、源图或 fieldTime，相位连续；从当前角度反向计算。若重置，会出现一次明显的粒子跳跃。

Android 原生渲染可用 Choreographer 协调显示帧；API 33 提供帧时间线与预期呈现时间。选择具体回调需按项目最低 API 版本处理，不能固定假设新 API 全部可用。Android NDK 官方文档

OpenHarmony 可从 NativeVSync 的 RequestFrame 接口建立渲染节拍，具体 API 版本及目标 HarmonyOS SDK 可用性必须由目标工程核对。OpenHarmony API 不是所有商用 HarmonyOS 版本能力的保证。OpenHarmony 官方接口头文件

4 秒机模导出的镜头轨迹只是展示，手机内容渲染不需要虚拟相机旋转。需要在锁角度、快速反转、系统中断与后台恢复时测试同一套进度规则。

7. 资源与中断状态机

Idle → Preparing → Active → Settling → Idle
                   ↓
               Cancelled / SurfaceLost → release after GPU completion

Active 时禁止替换已绑定的截图与 owner 纹理。窗口尺寸 / 布局 revision 改变，建立另一套资源，端点或明确的无跳变交接时机再替换。旧快照须等 GPU fence / 正常资源完成机制后释放。没有这样的同步不能声称零拷贝已完成。

后台、灭屏、Surface 销毁、来电打断时停止帧请求并释放资源；新会话重建。反向折展是同一会话的正常输入，不是 Cancelled。

04 · 验收与性能

1. 已有证据与边界

本包可重跑 node tests/clock.test.cjs 和浏览器 /tests/browser.html。实际运行结果保存 tests/browser-report.json，场景阶段图位于 examples。GLSL 编译、逻辑与图像测试通过不等于手机端帧率达标。

此前在设计电脑 Chrome 中，当前素材轮廓识别的中位耗时约内屏 23 ms / 外屏 24 ms；包含高分辨率透明切片准备约 98 ms / 50 ms；首次约 168 ms / 60 ms。该组是旧原型测量：固定截图、CPU / Canvas 路径，不含截图采集与 GPU 上传，不能当成手机“100 ms 内”的承诺。本包附上原始测量 JSON（如版本来源中存在）。本包独立实现另测数据见 browser-report，二者不直接当成同一性能测试。

原型默认两屏应用内容约 35 万 / 21 万细粒子，粒子数取决于掩码、分辨率、采样阈值与步长。它是桌面显卡视觉基准，不是手机上线预算。

2. 真机预算建议（需实测校准）

档位同时可见粒子总数起点分析尺寸起点使用方式
视觉基准不限到手机预算；本包 1.5 步长短边 320对齐形态、尺寸和方向，不能直接上线
常规试验3–9 万短边 240–320两屏合计，优先真正可见 Surface
低档试验1.5–3.5 万短边 160–240降采样，保留少量大颗粒与释放前沿
高档试验8–15 万短边 320仍须测功耗、带宽与持续发热

以上是开发起点而非认证上限。避免所有图块同间距硬采样后无限增加点。可按 alpha 面积分配配额、按块做分层抽样、屏外剔除；随机种子固定。减少数量时补偿覆盖感，但不要把所有点放大成大圆斑。

60 Hz 的显示帧周期约 16.67 ms，120 Hz 约 8.33 ms；这是整个系统帧的时间，不是本效果独占预算。给粒子 pass 多少 ms 由系统团队与真实场景共同分配。记录 P50 / P95 / P99、掉帧、GPU / CPU、峰值内存与 30 次连续折展后的热状态。

3. 与确认原型的关系

桌面 common、transport、base 和 desktop shader 从当前工程直接抽出；应用 shader 只保留确认版 fragments 分支，使用同一 birth 与自然流场参数，删去父块位移与整块模式控制。

为降低移植阅读成本，独立核心把应用块的可见内容合并为一张透明 source 纹理，样本仍逐块生成并保留 block ID。原机模使用每块纹理图集。两者的采样、UV 边缘过滤和随机序列可能存在微小差异；不声称独立示例与原机模视频逐像素一致。方向前沿、原位碎化、尺寸分布、底色和流场形态是共同基准。

原机模确认视频 references/应用内_确认版_闭合展开闭合.mp4 是用户最后指定覆盖的文件快照，不是之后导出的融合模式视频。它包括三维手机机框和镜头运动，粒子本身不需要三维自旋。示例 2D 视频仅展示算法，不替代机模确认视频。

原截图与模型快照的哈希见 provenance/source-map.json；素材文件哈希见 MANIFEST.sha256。测试报告记录本包真实运行时间和环境，不将旧测试记录复制为新的测试结论。

4. 生产实现必须替换的部分

  • Canvas getImageData / 每块 2×纹理复制：演示可读性实现，生产应改工作线程分析 + GPU 原图 / 掩码。
  • 默认 1.5 间距和两个屏幕同时满量渲染：视觉参考，手机按预算与可见性调节。
  • 浏览器动画时钟：换成目标系统呈现节拍与会话连续时钟。
  • 相片和固定桌面素材：换成宿主真实图层 / 快照，带 contentRevision 和资源同步。
  • 全局中性色启发式底色：宿主能提供时直接传准确背景；多色背景需分层处理。
  • GL_POINTS 固定 2×输出倍率：适配实际渲染尺度、硬件点尺寸能力；必要时实例化 quads。

6. 版本冻结

修改参数或算法时同时更新 shaders/*.glsl 与 shader-sources.js、设计规则、对照帧和测试报告。不得只修改视频或只改其中一份 shader。运行 node tools/verify-package.cjs 校验包内清单；任何后续内容修改都需要重新生成 MANIFEST。
