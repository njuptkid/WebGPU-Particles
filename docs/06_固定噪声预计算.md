# 固定噪声预计算实验

## 范围

优化前基线为本地 Git 提交 `ef78baa`。当前保留原始 shader，增加预计算变体，不更换 hash 函数或动态流场。

粒子固定的两个值在准备阶段计算：

```glsl
disturbance = noise(origin * .009) * .18
            + hash(floor(origin * .65)) * .20;
localNoise = noise(origin * .016);
```

每帧仍计算方向梯度，将 disturbance 合成为 birth。应用内 localAge 使用缓存的 localNoise。动态域扭曲的四次 noise、速度/尺寸/寿命的独立 hash 保持原样。

桌面每颗粒子移出每帧路径的是 5 次 hash 求值；应用是 9 次。不能据此按比例推算 GPU 耗时。

## 三种运行方式

```javascript
new ParticleRenderer({ ...model, precomputeNoise: false });       // 默认：原算法
new ParticleRenderer({ ...model, precomputeNoise: 'particles' }); // 粒子固定噪声
new ParticleRenderer({ ...model, precomputeNoise: 'all' });       // 粒子 + 原图释放扰动
```

兼容 `precomputeNoise: true`，含义与 `'all'` 相同。演示页两个复选框控制这三种模式。能力或缓存初始化失败时回退原算法，原因见 `noiseCacheStatus.reason`。

预计算目前是实验选项，默认保持原算法。本机样本波动明显，尚无可靠的整体加速结论；不能将减少 hash 次数等同于已提升性能。

### 粒子固定噪声

1. 使用原始 GPU hash/noise，在粒子真实源坐标上计算两个固定值。
2. 临时 RGBA8 图集中，每个值编码为两个通道，共 16 位。
3. WebGL1 准备阶段执行一次 `readPixels`，解码成两项 Float32 顶点属性，上传静态 VBO。
4. 删除临时图集、UV 缓冲、FBO 和烘焙程序。
5. 每帧读取属性，无新增顶点纹理采样，不执行 CPU 回读。

这会增加一次性的 GPU 同步及 CPU 解码开销，应在动画开始前准备，不能按帧调用。`noiseCacheStatus.prepareMs` 是准备调用的墙钟时间，包含回读等待和解码，不等同纯 GPU 烘焙时间。

持久 GPU 数据为每颗粒子 8 字节，默认应用双屏约 4.28 MiB；准备阶段的临时资源和 JS 数组不包含在此数字内。粒子源点或采样档位改变时需要重建；同一渲染器内角度、方向、流场时间变化无需重建。

第一版曾直接让粒子采样噪声图集，当前已改为静态属性，以避免逐顶点纹理访问。WebGL1 路径没有使用 transform feedback，也没有要求浮点渲染目标或顶点纹理单元。

### 原图释放扰动：实验选项

以实际离屏尺寸逐像素烘焙 disturbance，运行时以 `gl_FragCoord` 访问，避免翻转和像素中心错位。RGBA8 两通道编码，使用 NEAREST，不对不连续 hash 做线性过滤。

该路径额外增加默认双屏约 26.93 MiB 的持久纹理。数学计算减少不保证 GPU 更快：新增纹理读取和解码可能比原始 sin/hash 更昂贵。本机 RTX 3070 的初次测试出现原图 pass 回退，因此不默认启用，需要按设备测量。

## 精度与边界

disturbance 以 `[0,.38]` 编码，理想量化误差上界约 `0.38 / (2 * 65535)`；localNoise 以 `[0,1]` 编码。另有浮点运算与 shader 编译差异，所以不承诺逐像素相同。

背景、端点、轨迹、方向控制、颜色和粒子尺寸分布均沿用原算法。噪声缓存不会随着开合反转重新随机化。固定角度下动态流场继续演化。

## 构建与验收

修改 `src/shaders/*.glsl` 后运行：

```text
node tools/build-shaders.cjs
node tests/clock.test.cjs
```

生成器读取现有原始 shader，并加入缓存变体与烘焙 shader，统一输出 `src/shader-sources.js`。

本机 HTTP 服务下可访问：

- `/tests/browser.html`：原有 36 项验收。
- `/tests/noise.html`：桌面/应用、内外屏、双方向、多阶段、固定输入复现、动态流场及失败回退对照。
- `/tests/noise.html?benchmark=1`：增加 GPU 时间查询。

使用已安装的 Playwright 和本机 Chrome，可执行：

```text
node tools/run-browser-tests.cjs --benchmark
```

Playwright 通过正常模块解析或 `NODE_PATH` 提供，不是 demo 运行依赖。输出为 `tests/browser-precomputed-report.json` 和 `tests/noise-report.json`，保留历史 `tests/browser-report.json`。

对照统计以 8 位 RGBA 通道为单位：平均绝对差、最大绝对差、差异大于 8 的通道比例。阈值检验不替代真机视觉评审。

GPU 基准使用 `EXT_disjoint_timer_query`，不可用或时钟 disjoint 时明确记为无效；在同一 context 和资源上切换原始/缓存 shader，每组预热 8 次、测 11 次，三轮交替组顺序。报告三个组中位数的中位数和波动范围，共每种路径 33 个样本。计时固定 time=.73、fieldTime=1、direction=-1，分别隔离原图/粒子/组合。隔离项包含 renderRaw 的清屏等公共开销，不能直接相加。

基准不包含准备、截图、Canvas 2D 合成、真实双屏并发、整段折展或手机帧节拍；样本顺序、GPU 频率和系统负载会影响结果。`speedup` 小于 1 表示回退。不能将一次桌面中间帧测试当作真机性能认证。

## 当前验证结果

本机 Chrome 155 / ANGLE D3D11 / RTX 3070：时钟测试通过，预计算路径的原有浏览器验收 36 项通过，噪声对照 125 项通过。多阶段对照的最大平均通道差约 0.06681/255，没有通道差大于 8/255 的样本；这是所测样例范围的结论。

当前未证实性能提升。部分 GPU 计时组波动很大，不能汇总为整段加速比；原图缓存有明确的回退样本。例如应用内屏原图 pass 中位数从 0.887 ms 增至 1.500 ms，粒子属性缓存的粒子 pass 从 4.170 ms 增至 4.380 ms。这些是固定中间状态、包含公共清屏开销的样本，不是手机预算。

因此保留预计算实现与 A/B 验证入口，但不默认启用。后续若优化，应先确认实际瓶颈，并在固定负载、可控频率或目标设备上重测；不能沿用此前仅根据 hash 数量给出的乐观性能估计。
