# UI 消散中的细密编织纹诊断

后续修复已落地，默认路径已更换释放细粒度 hash。以下保留诊断过程；当前行为与测试见 `10_消散编织纹修复.md`。

用户确认问题是细密、规则的网格/编织纹。项目已有 `examples/app-inner-150.jpg` 的蓝色大卡片上可观察到相似斜纹。

## 诊断方式

使用原始 shader，内屏应用素材、角度 150°、fieldTime=1、sampleStep=1.5。逐项关闭 ribbon、双涡区、应用域扭曲、全部连续纵向场，另比较采样抖动、缩小粒径、关闭释放扰动、原图/粒子分层和仅替换细粒度 hash。共 14 组对照，无 GL 错误。

工具只在独立浏览器上下文中临时修改 shader 字符串，生成后恢复；没有修改正式算法或页面版本选项。

```text
node tools/run-browser-tests.cjs --cloth
```

需要 Playwright 和本机 Chrome。输出在 `tests/cloth-analysis/angle-150/`，另保留前一次 110° 诊断。

## 观察结果

- `baseOnly.png`：不绘制任何粒子，原图消散层仍有清晰斜向编织纹。因此粒子采样网格和运动场不是这次纹理的必要条件。
- `jitter.png`：粒子采样位置加入固定抖动，未消除原图上的编织纹。
- `noRibbon/noRoll/noBend/noCoherentY.png`：改变流场形状，仍保留原图过渡处细纹。
- `noFineBirthHash.png`：关闭 birth 中的细粒度 hash 后，规则斜纹明显减弱，但释放时序和粒化分布也改变，不能直接作为等价修复。
- `alternativeGrainBase.png`：保持 .20 扰动幅度及 floor(p*.65) 坐标，只把这项 sin 型 hash 换为浮点混合 hash，原图层的规则斜纹明显减弱，剩下更分散的随机颗粒。
- `baseOnly2x.png`：保留原始 2 倍输出，仍能观察到结构化纹理；缩放不是唯一来源。缩小显示可能继续改变或放大纹理的可见程度。

## 定位

主要问题在释放阈值：

```glsl
b = .045 + horizontalGradient
  + noise(p * .009) * .18
  + hash(floor(p * .65)) * .20;
remain = 1. - smoothstep(b, b + .26, time);
```

`hash(floor(p*.65))` 在约 1.54 逻辑像素的规则格点上提供固定扰动。当前 hash 使用 `fract(sin(dot(p,constants))*43758.5453)`，在本机和该坐标区域的结果存在可见空间结构。阈值扰动通过 alpha 淡出直接显现为有方向性的细密孔洞；其幅度 .20 相对淡出宽度 .26 较大，会增强可见性。

因果定位已落在这项扰动及其采样/数值结构；尚未独立证明是 sin 近似精度、点积降维相关性、fract 量化或各因素中的哪一个占主导。不能把全部原因简单归于 GPU 精度或 CSS 缩放。

之前的 hashfast/combined 仅替换动态 bend 中的 hash，释放阈值刻意保留原算法，因此不会解决这条路径上的纹理。

## 修复方向

优先为释放细粒度扰动使用空间分布更可靠的 hash 或静态蓝噪声，统一原图片元、粒子出生和预计算路径的规则。保持源坐标与种子固定，避免帧间重新随机导致闪烁。然后评估 .20 的扰动幅度和显示分辨率相关的滤波。

本轮替代 hash 是定位用候选，不是已验收的最终修复；还需检查其他角度、方向、素材、端点及性能。
