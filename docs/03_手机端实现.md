# 03 · 手机端实现方案

## 1. 推荐分工

以系统 / 桌面 / 窗口合成层能够控制内外屏 Surface 为前提，分成四个独立模块：快照输入、内容分离、粒子渲染、折展进度协调。不要依赖浏览器机模、截图视频或 JS 页面来驱动手机产品。

```text
Fold / VSync / Window lifecycle
             ↓
FoldController → FrameUniforms → NativeParticlePass → Screen Surface
       ↓                             ↑
SnapshotProvider → Worker extraction → PreparedSnapshot (revision + fence)
       └──── wallpaper / app base color (separate background pass)
```

`src/contracts.d.ts` 描述数据契约。`src/native/fold_clock.hpp` 只有可移植数学，不包含 SDK 桥接。GLSL 用 WebGL1 / GLES2 风格，可移到 GLES；Vulkan / 其他着色语言需转换接口与资源布局，不是直接改后缀。

## 2. 从真实 UI 获取输入

桌面优先从自有渲染树或已知图层取得“壁纸”和“上层内容”。这比从壁纸合成后的整屏截图重新识别图标可靠。桌面 source 必须是透明底，壁纸单独传给 background pass。

应用内只有截图时，运行本包 ContentRegions 检测。若宿主能提供可见卡片边界、圆角、裁剪和实际背景色，则优先由宿主提供，图像识别作为兜底。宿主元数据与截图必须在同一内容版本，且按照视觉遮挡确定所有权。

普通 App 不应假设有权限截取其他 App、锁屏或系统保护 Surface。系统 / 桌面集成方提供允许的快照 / 图层句柄；受保护内容用产品定义的占位或普通过渡，不绕过系统限制。Android 的 HardwareBuffer 仅是共享缓冲资源能力示例，不自动获得任意应用截图权限。[官方 HardwareBuffer 文档](https://developer.android.com/reference/android/hardware/HardwareBuffer)

本包演示图片导入与真实手机跨应用取图不是同一个问题；接口必须由目标团队实现并验证。

## 3. 应用分块步骤

1. 将截图分析副本缩放到短边 320，保留宽高比；原始高分辨率纹理用于最终显示。
2. 在中性色 RGB 量化直方图中找主簇，平均得到背景色；按颜色差建立前景掩码。
3. 形态学闭运算连接抗锯齿断边，连通域找到卡片与控件候选。
4. 对被底部浮层连接的封面行，分析上部持续竖向间隙拆出封面；对胶囊控件校验闭合边缘。
5. 大卡片优先，压制内嵌纹理误检；保留浮层遮挡；对未占有的文字做连通组。
6. 为每个源像素给出唯一 owner ID；小断边根据邻域归属附着。每块保留真实 alpha 掩码，不能只输出矩形裁切。
7. 对全部卡片 / 控件 / 文字块分别采样，跳过背景；**不做大卡片二次切分**。
8. 不属于内容块的残余区域单独绘制，其细节可原位淡出；应用底色永久画满。

详见 `src/content-regions.js` 与 `src/app-block-extractor.js`。检测是启发式图像处理，不是 OCR / 语义 AI，不保证任意截图都完整正确。深色、浅色、复杂摄影背景、透明控件和渐变都应加入真实测试集。

## 4. 避免准备时间吃掉动画

本包 build() 为便于读懂仍是同步 CPU + Canvas 参考实现，**生产禁止在 UI / 渲染线程临时照搬这段全流程**。

推荐：低分辨率分析放工作线程；原截图留在 GPU；把 owner / mask 作为低分辨率纹理或稀疏区域索引上传。用 source UV + mask 取样，不逐块复制高分辨率截图。粒子顶点 / 实例缓冲只在快照变更时创建。

后台缓存键至少包括屏幕、实际尺寸、contentRevision、主题、适配方式和识别参数。现有原型只按屏幕与参数缓存，是固定示例素材的简化，不能直接用于“每次都是新界面”的手机。

开始折展时的次序：

```text
若有匹配本次 revision 的 PreparedSnapshot：立即使用
否则保持当前真实界面，同时后台准备低分辨率分析
若准备在约定首帧截止前完成：原位接入细粒子
否则：本次使用快速内容掩码 / 宿主布局，或产品批准的普通过渡
```

建议准备截止目标 1–2 个显示帧，仅为工程目标，不是已达到指标。不能阻塞合页输入，不能等 100 ms 再从头重播；也不能用上一张应用界面的切片假装已准备。复杂界面超时应记录原因，具体降级需设计 / 开发共同确认。

## 5. GPU 数据与绘制

原生建议数据：源纹理、owner / alpha 纹理、可选 block bounds、静态样本缓冲、背景纹理 / 底色。每个样本至少含全局源位置与随机种子；block ID 可用于调试、采样配额和失效重建，不作为整块位移矩阵。

每帧仅更新 resolution、tau、direction、fieldTime 与输出倍率。顺序：

1. 画桌面壁纸或不透明应用底色。
2. 应用残余细节在原位淡出，始终有底色填充。
3. 画内容纹理：对源像素算 birth / remain，几何位置固定。
4. 画柔边点精灵：相同 birth 计算 age，从源像素起点进入全屏流场。
5. q=0 交给真实完整界面；q=1 只保留底层。静止时不重复积累或清空后漏画。

粒子位置用源坐标 + 解析轨迹，不在 CPU 每帧更新几十万个点。GPU 并行计算；不需要先上 compute 才能实现。平台点精灵尺寸范围、精度和驱动行为不满足时，用实例化小四边形替代 GL_POINTS，并保持相同柔边和尺寸分布。

WebGL `UNPACK_PREMULTIPLY_ALPHA_WEBGL` 是浏览器特有设置，原生上传时要查清 PixelMap / Buffer 的实际像素格式和 alpha 约定，不能假设原生会自动做相同转换。HDR / 广色域必须明确采样与混合色域，不把 sRGB 参考值直接套在线性空间。

## 6. VSync 与时间

foldAngle 决定转化进度，VSync 决定提交节奏，fieldTime 决定持续的涡流形状。反转开合时不重置 seed、源图或 fieldTime，相位连续；从当前角度反向计算。若重置，会出现一次明显的粒子跳跃。

Android 原生渲染可用 Choreographer 协调显示帧；API 33 提供帧时间线与预期呈现时间。选择具体回调需按项目最低 API 版本处理，不能固定假设新 API 全部可用。[Android NDK 官方文档](https://developer.android.com/ndk/reference/group/choreographer)

OpenHarmony 可从 NativeVSync 的 RequestFrame 接口建立渲染节拍，具体 API 版本及目标 HarmonyOS SDK 可用性必须由目标工程核对。OpenHarmony API 不是所有商用 HarmonyOS 版本能力的保证。[OpenHarmony 官方接口头文件](https://gitee.com/openharmony/interface_sdk_c/blob/8161da22f6dd46ecf79dec8bcb745d3b9a06d5aa/graphic/graphic_2d/native_vsync/native_vsync.h)

4 秒机模导出的镜头轨迹只是展示，手机内容渲染不需要虚拟相机旋转。需要在锁角度、快速反转、系统中断与后台恢复时测试同一套进度规则。

## 7. 资源与中断状态机

```text
Idle → Preparing → Active → Settling → Idle
                   ↓
               Cancelled / SurfaceLost → release after GPU completion
```

Active 时禁止替换已绑定的截图与 owner 纹理。窗口尺寸 / 布局 revision 改变，建立另一套资源，端点或明确的无跳变交接时机再替换。旧快照须等 GPU fence / 正常资源完成机制后释放。没有这样的同步不能声称零拷贝已完成。

后台、灭屏、Surface 销毁、来电打断时停止帧请求并释放资源；新会话重建。反向折展是同一会话的正常输入，不是 Cancelled。

## 8. 分阶段落地

| 阶段 | 内容 | 退出条件 |
| --- | --- | --- |
| P0 视觉对齐 | 两屏静态输入、两方向、同 GLSL、同粒子尺寸与背景 | 基准帧与视频评审通过 |
| P1 自有桌面 | 真图层接入，壁纸分离，折展连续输入 | 无提前空屏、无背景粒化、反转连续 |
| P2 应用快照 | 内容版本、后台识别、掩码上传和缓存 | 每次新界面无错图 / 陈旧掩码 |
| P3 真机优化 | 粒子预算、分辨率、VSync、功耗、失败降级 | 目标设备矩阵实测通过 |
| P4 系统集成 | Surface 生命周期、受保护内容、端点交真实 UI | 中断 / 旋转 / 多任务回归通过 |

目前本包完成的是算法参考、示例输入与浏览器验证。P1–P4 不是已实现的手机代码。
