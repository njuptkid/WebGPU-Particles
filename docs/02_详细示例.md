# 02 · 详细示例与失败对照

## A. 桌面：图标、标题、卡片同时属于可见内容

输入样例见 `demo/assets/desktop-{inner,outer}-content.png`（透明底）和对应 wallpaper.png。content 包含 widgets、icons、dock、status 四类上层的合成；壁纸不在 alpha 掩码内。

假设外屏一个图标包围框 x=80..150，标题 x=70..160。不要把两者各变成一个大的纹理平面飞走。对透明合成图按 1.5 逻辑像素间距采样，只有 alpha>16/255 的源像素产生点。图标的形状与文字笔画会自然保留在释放初期，随后被统一流场拉散。

同一图标左右笔画的 birth 不同，因此边缘能看到逐渐碎化。大时钟“10:08”也按笔画像素碎化，不拆成五张整体飞行的纹理。文件夹内部所有可见像素均可采样；不要把文件夹底框整体当作一个粒子。

内屏出现阶段 q 从 1 减小到 0：源纹理从左往右逐渐恢复，粒子沿从左往右的实际动势收敛。端点 q=0 必须像素级恢复输入内容＋壁纸，不能剩下最后一层漂浮的尘。

## B. 应用外屏：完整主视觉原位碎化

原始截图见 `demo/assets/app-outer.jpg`。识别叠图见 `examples/app-outer-识别预览.jpg`；精确逻辑坐标以 `examples/app-blocks.json` 为准，不能把本文近似尺寸作为固定模板。

典型结果：

| 内容 | 示例识别结构 | 运动规则 |
| --- | --- | --- |
| 顶部主视觉 | 一张约 632×510 的大卡片，含图中标题、人物和覆盖在主视觉内的内容 | 整卡不追加切线、不平移；卡片内像素按全屏横坐标逐渐碎化 |
| 底部封面 | 三个独立封面，约 190×195 | 分别保留掩码归属，进入同一流场 |
| 分类胶囊 | 识别成完整闭合控件 | 按掩码采样，不把底色间隙做成粒子 |
| 浮动导航栏 | 独立控件；覆盖关系保留，不能与封面重复拥有同一像素 | 与其他内容共享前沿；不要重复采样造成导航区域发亮 |
| 未组成闭合块的文字 | 文字连通组 | 作为小内容单元逐像素释放 |

样例外屏总计 10 个卡片 / 控件块＋2 组文字，即 12 个采样内容单元。主视觉中“人物”没有被语义抠图，是完整主视觉卡片的一部分。

默认外屏从左向右凝聚：展开时，右侧先碎化、粒子向左走；闭合时反播，左侧先建立界面、右侧稍后完成。宏观扰动跨越主视觉、封面和控件，使粒子不像多个独立方形云团。

## C. 应用内屏：横幅保持完整

内屏原图与识别图分别见 `demo/assets/app-inner.jpg`、`examples/app-inner-识别预览.jpg`。典型识别为两张完整横幅、六张封面和多个搜索 / 分类 / 导航控件。

样例内屏为 20 个卡片 / 控件块＋6 组文字，共 26 个采样内容单元。较大横幅约 592×335；它仍是一张卡片，不能沿中心拆为三块。全部未被别的块覆盖的可见像素由同一块拥有，圆角与遮挡由 alpha 掩码保留。

需要关注的中间态：右侧横幅可已经大量变成粒子，左侧横幅仍保留大部分内容；同一横幅自身也有渐进碎化，而不是两张横幅依次整张淡掉。识别是局部的，释放前沿与运动场是全屏连续的。

## D. 用角度理解双屏过程

| 角度 | 外屏 q | 内屏 q | 理想观察 |
| --- | --- | --- | --- |
| 0° | 0 | 1 | 外屏完整，内屏仅底层 |
| 30° | .167 | .833 | 外屏一侧开始粒化；内屏粒子已经可见，无长时间全空 |
| 60° | .333 | .667 | 外屏存在明显方向性过渡带；内屏正在从粒子恢复 |
| 90° | .5 | .5 | 双屏均处于连续中间态；不能在系统折叠阈值上突变 |
| 120° | .667 | .333 | 外屏主体粒子化，内屏大部分内容恢复但仍有方向性边界 |
| 150° | .833 | .167 | 内屏趋近完整，外屏仍有残余流动并接近背景 |
| 180° | 1 | 0 | 内屏完整，外屏仅底层 |

实际完整率受源图、噪声和 tau 非线性映射影响；表格不是硬切状态或新加时间段。4 秒机模视频包括先开后合两段，是展示节奏，不是要求手机每次动作都固定 4 秒。

## E. 输入新界面的示例流程

```text
收到 fold 开始事件
→ 固定本次出屏快照 revision=R17
→ 后台对低分辨率副本检测块 / 背景色
→ 掩码与 sourceTexture 必须同属 R17
→ 生成本次静态粒子 buffer，只更新进度和相位
→ 新屏幕布局已就绪时，使用其独立快照 R18 建立入屏内容
→ 整次会话冻结各自资源，不在中间把 R17 的图替换为 R19
→ 进度到端点后，交回真实 UI；后台释放不再需要的纹理
```

两块屏幕的布局可以不同，粒子不需要一一对应。颜色和运动让视觉连贯，但不能为了“一一对应”强行把外屏卡片拉伸成内屏卡片。

## F. 必须纠正的失败示例

| 现象 | 原因 | 正确实现 |
| --- | --- | --- |
| 整屏突然从界面跳成尘 | 一次切换截图和粒子开关 | 保留同一源图，片元级 birth 连续退场，粒子 age 同源 |
| 每张卡整张同时淡出 | 使用块中心 age 控制所有像素 | 每个源像素按全屏横坐标算 birth |
| 卡片先飘走再碎 | 复用整块位移 / 自旋 | 图块 quad 的位置、比例和朝向始终固定；只有粒子移动 |
| 出现方形 / 长条云团 | 每块局部坐标重复计算涡流，或父块位移一直叠加 | 所有粒子按屏幕全局坐标进入共同流场 |
| 流动均匀像一阵喷雾 | 只有独立随机散开 | 叠加大尺度、持续变化的涡区和域扭曲，形成疏密变化 |
| 涡流倒着拽一部分粒子 | 对称圆形旋转场 | 主方向保持下游，扭曲主要作用于横截面 |
| 挖出的卡片下面出现壁纸窟窿 | 底图仍有透明掩码 | 最底层先完整填应用底色，再画剩余细节与粒子 |
| 粒子少、转化时画面变薄 | 采样过稀、尺寸全都太小或 alpha 过低 | 细粒子＋少量大粒子；按覆盖感验收，而非只看个数 |
| 转化有黑边 | 重复预乘 / 非预乘混合不一致 | 全链路预乘；需要直色时只临时除 alpha，最终只乘一次 |
| 长时间空白壁纸 / 底色 | 入屏动画启动阈值晚，或准备结果阻塞 | 共享连续进度、提前准备；超时走定义好的降级 |
