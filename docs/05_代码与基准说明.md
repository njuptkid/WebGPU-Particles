# 05 · 代码与基准说明

## 1. 源码职责

| 文件 | 职责 |
| --- | --- |
| src/fold-clock.js | 角度 → 双屏 dissolve / time / direction，可独立测试 |
| src/content-regions.js | 从现有项目原样提取的本地轮廓与连通区域分析 |
| src/app-block-extractor.js | 只保留完整内容块和透明掩码；无二次细分；从截图构建 content / background |
| src/particle-renderer.js | 透明内容取样、静态 buffer、基础纹理退场与粒子 GPU pass |
| src/shaders/common.glsl | hash / noise / birth，统一方向性前沿 |
| src/shaders/transport.glsl | 原版屏幕连续输运与动态涡流 |
| src/shaders/baseVertex.glsl | 全屏源图固定不动的 quad |
| src/shaders/baseFragment.glsl | 按源像素 birth 逐渐退场，无整块透明度 |
| src/shaders/desktopVertex.glsl | 桌面原版点位、颜色、尺寸与寿命 |
| src/shaders/appVertex.glsl | 应用内原位细粒子、全局流场与额外域扭曲 |
| src/shaders/pointFragment.glsl | 柔边圆点和预乘 alpha 输出 |
| src/shader-sources.js | 上述 shader 的浏览器打包副本，不需要构建工具 |
| src/native/fold_clock.hpp | C++17 数学片段；不含系统 / GPU API，不声称已编译原生工程 |
| src/contracts.d.ts | 生产模块接入契约示例，句柄由目标平台定义 |

独立核心不存在整图标 / 整卡飞行、三维自旋、融合碎片状态或光照 pass；也不引用原工程的 whole-icon-scene.js / progressive-hybrid.js。原工程这些文件只作为提取时的比对来源，在 provenance 中记录 SHA-256，不直接交付这些多模式实现。

## 2. 最小调用示例

```javascript
// screenshotCanvas 已由业务读取，本例以外屏逻辑尺寸构建。
const model = AppBlockExtractor.build(screenshotCanvas, 632, 924,
  { size:100, variation:60, edge:75 });
const fx = new ParticleRenderer({
  ...model, fullSource:model.source, source:model.content, scene:'app', sampleStep:1.5
});
const state = FoldClock.pose(foldAngle, 'outer', true);
fx.draw(ctx, outputWidth, outputHeight,
  { ...state, fieldTime:sessionElapsedSeconds });
// 会话结束且不再使用时：fx.dispose()
```

桌面传透明 contentCanvas 和单独 wallpaperCanvas：

```javascript
const fx = new ParticleRenderer({ w:1292, h:914,
  source:contentCanvas, background:wallpaperCanvas, scene:'desktop' });
```

输入截图适配 / 裁切在 build 前完成；本包 demo 与原工程 contain 样例几乎同宽高比。实际应用不得拉伸导致坐标与截图对不上。

## 3. 与确认原型的关系

桌面 common、transport、base 和 desktop shader 从当前工程直接抽出；应用 shader 只保留确认版 fragments 分支，使用同一 birth 与自然流场参数，删去父块位移与整块模式控制。

为降低移植阅读成本，独立核心把应用块的可见内容合并为一张透明 source 纹理，样本仍逐块生成并保留 block ID。原机模使用每块纹理图集。两者的采样、UV 边缘过滤和随机序列可能存在微小差异；**不声称独立示例与原机模视频逐像素一致**。方向前沿、原位碎化、尺寸分布、底色和流场形态是共同基准。

原机模确认视频 `references/应用内_确认版_闭合展开闭合.mp4` 是用户最后指定覆盖的文件快照，不是之后导出的融合模式视频。它包括三维手机机框和镜头运动，粒子本身不需要三维自旋。示例 2D 视频仅展示算法，不替代机模确认视频。

原截图与模型快照的哈希见 provenance/source-map.json；素材文件哈希见 MANIFEST.sha256。测试报告记录本包真实运行时间和环境，不将旧测试记录复制为新的测试结论。

## 4. 生产实现必须替换的部分

- Canvas getImageData / 每块 2×纹理复制：演示可读性实现，生产应改工作线程分析 + GPU 原图 / 掩码。
- 默认 1.5 间距和两个屏幕同时满量渲染：视觉参考，手机按预算与可见性调节。
- 浏览器动画时钟：换成目标系统呈现节拍与会话连续时钟。
- 相片和固定桌面素材：换成宿主真实图层 / 快照，带 contentRevision 和资源同步。
- 全局中性色启发式底色：宿主能提供时直接传准确背景；多色背景需分层处理。
- GL_POINTS 固定 2×输出倍率：适配实际渲染尺度、硬件点尺寸能力；必要时实例化 quads。

## 5. 已验证 / 未验证

浏览器报告覆盖实际样例识别、完整卡片、逐像素重组、采样归属、背景、端点、双方向前沿、时间形变、GL 错误和固定输入复现。

未验证：原生 C++ 编译与 SDK 接入、任何具体手机 GPU 的兼容性、120 Hz、HDR、跨应用截图权限、受保护内容、功耗、温控、系统合页传感器输入、原生 Surface 生命周期。它们必须按实施和验收文档继续完成。

## 6. 版本冻结

修改参数或算法时同时更新 shaders/*.glsl 与 shader-sources.js、设计规则、对照帧和测试报告。不得只修改视频或只改其中一份 shader。运行 `node tools/verify-package.cjs` 校验包内清单；任何后续内容修改都需要重新生成 MANIFEST。
