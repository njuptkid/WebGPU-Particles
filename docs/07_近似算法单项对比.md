# 近似算法单项对比

入口：`/demo/compare.html`。左侧始终使用原算法，右侧从下拉框选择一个实验。所有近似实验都关闭固定噪声预计算，不混合多个改动。

## 实验列表

| 标识 | 修改 | 未修改的部分 | 预期视觉差异 |
| --- | --- | --- | --- |
| uniforms | 将 transport 中 8 个全局三角函数项移至每帧 CPU 计算，通过 uniform 传入 | 空间波形、噪声、随机属性 | 仅浮点数值差异；不保证逐像素相同 |
| noise2 | 动态 bend 从四次值噪声改为两次，移除嵌套 warp | 原位释放、基础输运、双涡区、尺寸、寿命 | 扭曲可能更规则；仅影响应用内 |
| hashfast | 仅将动态 bend 的四次 noise 内部 hash 改为无 sin 的浮点混合 | 噪声调用次数、释放 noise/hash、静态随机属性 | 随机流场改变；仅影响应用内 |
| envelope | 双涡区包络从 exp(-z) 改为 max(0,1-z/4)^4 | 运动方向、涡区相位与幅度公式 | 影响范围与衰减曲线改变 |
| radial | 柔边圆点改为 max(0,1-4*dot(d,d))^2 | 点大小、粒子位置、颜色与寿命 | 透明度覆盖分布改变 |
| wave | 仅将 4 个依赖空间坐标的正弦换成平滑三角波 | hash、noise、全局相位 sin/cos | 周期曲线有小幅差异 |
| growth | 将 1-exp(-x) 换成 1-1/(1+x+x²/2+x³/6) | 释放与粒子属性 | 扩散和扰动介入节奏改变 |

另有原算法自对照，以及上一轮的两种预计算模式。近似实验均保留原始内容消散 pass，避免原图释放与粒子出生时机不一致。

## 怎么比较

1. 默认应用内、内屏，先观察 noise2。点击“同步播放开合”，两侧共享同一个角度与流场时间。
2. 暂停，拖动角度检查局部结构。通过“仅粒子”隔离轨迹，通过“仅原始内容消散”确认释放前沿未改。
3. 勾选“流场持续演化”，检查形状是否自然演化、出现网格或重复条纹。左右仍使用同一时间。
4. 切换内外屏、方向、桌面，并比较大粒子、文字轮廓与浓度。noise2/hashfast 在桌面上应不改变结果。
5. 每次只选择一个方案，不用像素差越小就越好来判断改变随机场的实验。差异图用于定位变化。

播放状态的快慢不能作为性能结论，因为视觉页同时绘制两套 GPU 场景，还执行 Canvas 2D 合成和像素差异读取。

## GPU 计时

点击“测量当前实验 GPU 耗时”会冻结控制参数、临时锁定控件。在左侧同一 WebGL context、相同源纹理和缓冲上交替切换原始与实验程序，避免跨 context 资源驻留差异。

- 使用 `EXT_disjoint_timer_query`，不可用、超时或 disjoint 时不提供 CPU 替代数据。
- 每种路径预热 8 次，在计时前使用 finish 等待预热完成；finish 的 CPU 墙钟时间不计入结果。
- 9 对 A/B 样本，交替 AB/BA 顺序。每次查询覆盖 4 次 renderRaw，结果除以 4。
- 报告中位数、P10/P90、原始样本、耗时变化及波动标识。P90-P10 超过中位数的 25% 时标为波动较大。
- “完整动效”的 GPU 计时覆盖内部原图和粒子 pass，不包含 Canvas 2D、快照准备、CPU 公共参数计算或差异图。分层计时仍含清屏等公共成本。
- 全局 uniform 实验将计算移到 CPU；GPU 耗时减少不代表 CPU/GPU 总开销一定减少。
- GLSL 源码运算数量不等于原生 GPU 指令数量。本项目没有提供驱动编译器 ISA 分析。

完整端点走直接绘制原图/背景路径，而内部 renderRaw 计时仍会提交 shader，因此不应将端点的内部计时视作最终画面成本。应在中间角度比较，并覆盖多个阶段和目标设备。

## 实现位置

- `tools/shader-experiments.cjs`：从原始 shader 生成独立变体，检查替换标记，保留原始 GLSL 文件。
- `src/shaders/fastMotionNoise.glsl` 等：近似函数及圆点候选。
- `src/particle-renderer.js`：`shaderVariant` 参数、公共 uniform 上传。
- `src/shader-benchmark.js`：同 context GPU A/B 测量，结束后恢复原始程序和绘制状态。
- `tests/experiments.test.js`：样本数、原图 pass、端点、固定输入复现、场演化、覆盖和 GL 错误检查。

测试端点允许最大 2/255、平均小于 0.02/255 的 Canvas 合成差异。对于改变流场的实验，记录像素差和 alpha 覆盖比，不要求接近原版每个像素。当前自动覆盖是固定中间状态与端点，不能替代整段动效的视觉评审。

## 运行

```text
node tools/build-shaders.cjs
node tests/clock.test.cjs
node tools/run-browser-tests.cjs --experiments --benchmark
```

最后一条需要已安装 Playwright 和本机 Chrome，可通过 NODE_PATH 提供模块。输出 `tests/experiments-report.json` 和 `tests/experiments-preview.png`，不覆盖历史噪声预计算报告。

## 首轮结果

Chrome 155 / ANGLE D3D11 / RTX 3070：325 项实验与页面检查通过。另行重跑原有 36 项验收和 125 项噪声预计算检查，也通过。

视觉差异在采样间距 4、time=.73、fieldTime=1、负方向、应用内屏的内部过渡层上统计。平均绝对通道差如下；这些不是最终画面评分，也不能跨随机场直接按差值评判优劣。

| 实验 | 平均差 /255 | alpha 总量比（实验/原始） |
| --- | ---: | ---: |
| uniforms | 0.00043 | 1.0000 |
| noise2 | 20.994 | 1.0004 |
| hashfast | 22.125 | 1.0059 |
| envelope | 13.544 | 0.9997 |
| radial | 1.730 | 0.9440 |
| wave | 5.689 | 1.0003 |
| growth | 7.768 | 1.0006 |

公共参数方案差异很小；噪声简化和换 hash 的随机形态改变明显。radial 的透明覆盖总量减少约 5.6%，不应作为纯粹等价的圆点加速。

GPU 基准在应用内屏、采样间距 1.5、time=.73 下分别测粒子和内部组合 pass。16 组包含原算法自对照；15 组被标为波动较大，唯一未标波动组的变化也只有约 -0.34%。自对照粒子组出现约 +22% 差异，说明当前测量环境不足以可靠区分候选性能。首轮不认定任何近似已获得稳定加速，也不据此选出性能最优方案。

详细样本与 P10/P90 保存在实验报告中。对比页可在用户当前浏览器/GPU 环境重复测量；正式决策仍需可控负载与目标设备测试。
